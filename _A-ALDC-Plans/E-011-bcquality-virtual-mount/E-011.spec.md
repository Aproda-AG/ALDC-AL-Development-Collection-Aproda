## 0. Q-9 — constant workspace entry (decided 2026-11-13: (a))

The whole point is that developers never overwrite each other's tracked workspace file.

The mount setting is **per workstation** (`application` scope, Q-1), but the `*.code-workspace` file is **tracked
and shared**. If the workspace entry depended on the mount (Q-5: `uri` in virtual mode, `path` in junction/none
mode), two developers with different settings would rewrite the tracked file back and forth — git churn on every
window start. D-49 avoided exactly this ("nothing per workstation in tracked files").

**Decision (used in the rest of this spec):** the workspace entry is **constant** in every mode:

```jsonc
{ "name": ".external", "uri": "aldc-external:/" }
```

The mount setting changes only what the extension does **behind** that root:

| Mount | `aldc-external:/` shows | Junction on disk |
|---|---|---|
| `virtual` (default) | real files of `<repo>/.external/` + virtual `bcquality/` | none (an existing one is removed, link only) |
| `junction` | same as `virtual` | `.external/bcquality` created (for path-based tools, access rule step 2c) |
| `none` | real files of `<repo>/.external/` only (README) | none |

The Explorer looks the same for everyone, the tracked file never changes after the one-time migration, and the
junction becomes what it is good for: a disk path for path-based tools on local drives. Q-5 and Q-8 keep their
intent (one `.external` root, README visible in every mode); only "in junction/none mode the root points back to
the real folder" is replaced. Without the extension the root is unavailable — accepted (M6 out of scope).

## 2. File system provider `aldc-external:` (X-02)

### 2.1 Registration

`vscode.workspace.registerFileSystemProvider("aldc-external", provider, { isReadonly: true, isCaseSensitive: false })`
at activation, unconditionally (also with `autoReconcile = false` and in non-AL windows), so the constant workspace
root resolves in every window of the project. `isReadonly` makes editors refuse writes up front (finding A7: agent
edit tools may still change the editor buffer — accepted).

### 2.2 Repository

The provider serves the repository resolved by `resolveAldcRepository()` (git root, same as `#aldcConfiguration`).
Not configured → every call fails with `Unavailable` *"No ALDC repository in this window."*

### 2.3 Namespace

| URI path | Served from | Kind |
|---|---|---|
| `/` | union of (a) the entries of `<repo>/.external/` **except** names that are sources, and (b) one directory per active source | directory |
| `/<file-or-dir>` (not a source name) | `<repo>/.external/<…>` — passthrough, read-only | as on disk; reparse points (junctions/symlinks) are **not** listed and not followed |
| `/<source>/…` | the source's resolved root (`bcquality` → `resolveBcquality().root`) | as on disk under that root |

Active sources: `bcquality` when mount ≠ `none` and `aldc.yaml → external.bcquality.enabled ≠ false`. Further
sources (G-1a) are added to a static registry `{ name, resolve() }` in code; an `external.<name>` block without a
registry entry is ignored with one log line. A real `.external/bcquality` (junction mode) is hidden in favour of the
virtual source — both show the same clone; the virtual one works on every drive.

URI forms: `aldc-external:/x` and `aldc-external:///x` are equal. With a non-empty authority (`aldc-external://bcquality/x`)
the authority is treated as the first path segment (the spike rejected that form; tolerated now). Paths are
normalised with POSIX semantics, then contained (§2.4).

### 2.4 Containment

- Source paths: `resolveContained(root, relative)` (existing `src/bcquality/containment.ts`).
- Passthrough paths: the same function with `<repo>/.external` as root.
- `..` that would leave `/` → `FileNotFound` (never `NoPermissions`, never content from outside). A `..` that stays
  inside (`/bcquality/skills/..`) is allowed (spike was over-conservative, finding A8).

### 2.5 Operations

| Operation | Behaviour |
|---|---|
| `stat`, `readDirectory`, `readFile` | as §2.3; `FileType.Directory`/`File`; sizes/mtimes from disk |
| `writeFile`, `createDirectory`, `delete`, `rename` | `FileSystemError.NoPermissions("aldc-external:/ is read-only")` |
| source unresolved | `FileSystemError.Unavailable("BCQuality clone not resolved. Tried: <source>=<path|unset>[<verdict>]; …")` — same candidate list as the spike (finding A13 PASS) |
| missing file inside a resolved source | `FileSystemError.FileNotFound(uri)` |
| `watch` | returns a disposable; no per-file watching (§2.6 covers resolution changes) |

### 2.6 Change events

`onDidChangeFile` fires `{ type: Changed, uri: aldc-external:/ }` and for each source root when the resolved root of
a source changes, when `external.mount` changes, or when `aldc.yaml` changes (existing watchers where present;
otherwise on the settings-change event). Cached content is not kept by the provider; VS Code may keep open documents
(spike A12 note — accepted).

## 3. Resolver changes (X-03, `src/bcquality/resolve.ts`)

1. **Non-file workspace folders are skipped** in the `workspaceFolder` rung (`folder.uri.scheme !== "file"`), or the
   constant `aldc-external:/` root would be probed as `fsPath` `/`.
2. **Invalid explicit candidate (Q-6, A12):** when the `setting` or `environment` candidate is set but its verdict is
   not `verified`, and a later rung verifies, log a warning and show **one** notification per distinct value and
   window: *"aprodaAldc.bcquality.path points to `<path>` (`<verdict>`); BCQuality is served from `<root>`
   (`<source>`)."* Buttons *Open Settings* / *Show BCQuality Status*. `devRoot` and `aldcYaml` are defaults and never
   warn. The resolver stays side-effect free; the warning is emitted by the caller that runs on activation/reconcile.

## 6. Reconcile and migration (X-06, `src/workspace/bcqualityRoot.ts`)

Runs on activation (`reconcileBcqualityOnStartup`) and on a change of `external.mount` / `bcquality.path`.

1. `enabled: false` → remove the junction (link only) — unchanged kill-switch, independent of `autoReconcile`.
2. `autoReconcile = false` → stop (log line).
3. **Workspace migration (one time per project):**
   - target = `vscode.workspace.workspaceFile` if it is a `file:` URI inside the repository root; otherwise skip
     with a log hint (single-folder windows have no workspace file);
   - classify the `folders[]` entries (comment-preserving parse with `jsonc-parser`):

     | Form | Detection | Action |
     |---|---|---|
     | constant entry | `uri == "aldc-external:/"` | keep (exactly one; drop duplicates) |
     | `.external` path root (D-49 layout) | `name == ".external"` or `path` normalising to `.external` | replace by the constant entry |
     | **legacy direct clone root** (pre-D-49, path differed per developer: `../BCQuality-Aproda`, `../../BCQuality-Aproda`, an absolute path, `bcquality-aproda`, …) | last path segment matches `^bcquality(-aproda)?$` (case-insensitive) **or** the path resolves to a folder containing `skills/entry.md` | remove; add the constant entry if none exists |
     | anything else | — | untouched |

   - with a legacy root removed, also remove `search.exclude` / `files.watcherExclude` globs that name it, and
     `BCQUALITY_HOME` under `settings.terminal.integrated.env.*` (container key removed when empty) — the same
     clean-up `Migrate-AprodaProjectLayout.ps1` does today, now comment-preserving;
   - a missing `.external` entry (no form above) is **added** at the end (same as `Initialize`);
   - nothing to change → no write. Edits via `jsonc-parser` `modify` + `applyEdits` (comments and formatting kept),
     written UTF-8 without BOM, every change logged.
   - If the file does not parse: warning with the manual edit, no write.
   - Because every developer's file converges to the same entry, simultaneous migrations by two developers can at
     worst produce a trivial merge conflict with identical content on both sides.
4. `BCQUALITY_HOME` Global setting: unchanged behaviour.
5. **Junction:** mount `junction` → `createBcqualityLink` (existing, incl. `0.2.2` warnings); mount `virtual`/`none`
   → `removeBcqualityLink` if a link exists (link only; on failure the `0.2.2` network-drive warning with
   `cmd /c rmdir`).

The write in step 3 makes VS Code reload the changed root; `.external` is never the first root, so the extension
host is not restarted. The reconcile is idempotent: a second run changes nothing.

## 8. Extension package (X-07)

Version `0.3.0`; `CHANGELOG.md`; `package.json` contributions (setting, command, menu); tests (§ test plan).

## 9. Rollout order

Extension `0.3.0` first (the provider must exist before a workspace file carries the `uri` entry), then the layer
release (seed, scripts, prose). A project migrated by one developer's `0.3.0` shows an unavailable `.external` root
to colleagues on older versions until they update — release note.

## 10. Out of scope

Search/symbol providers for the virtual root; a generic resolver for sources other than BCQuality; per-source mount
overrides (Q-1); BCQuality install/update.
