## 2. Shared contracts

### 2.1 Conventions (all PowerShell deliverables)

- **pwsh 7 only** (C-5). Scripts check `$PSVersionTable.PSVersion.Major -ge 7` where they are entry points.
- **SRP-safe loading:** every script is loaded with `. ([ScriptBlock]::Create((Get-Content -LiteralPath <p> -Raw)))`;
  no `Import-Module`, no `. <path>`, no `& <path>.ps1`. `$PSScriptRoot` is empty under this loading — paths are
  passed in as parameters.
- **No secrets** in files, logs, global/user/terminal environment, or command lines. A credential is read
  from the Fkh store (D-43) and handed only to one child process (`ProcessStartInfo.Environment`) or one
  `HttpClient`.
- **Library functions** (§2.5) write nothing to any stream except their return value; warnings are returned
  as data (`Warnings` property). Only entry points log.
- `Set-StrictMode -Version Latest` in every new script; property reads on JSON objects go through
  `PSObject.Properties` checks.

### 2.2 `aldc.local.json` (schema version 1)

**Location.** Next to the resolved `aldc.yaml`, same two-rung rule as `aldc.yaml` itself:
`<repo>/.github/aldc.yaml` exists → `<repo>/.github/aldc.local.json`; else `<repo>/aldc.yaml` exists →
`<repo>/aldc.local.json`; else no location (state `noToolkit`). `<repo>` is the git root (first ancestor that
contains a `.git` file or folder).

**Content** — strict JSON (no comments, no trailing commas), UTF-8 without BOM, 2-space indent, trailing
newline:

```json
{
  "version": 1,
  "target": {
    "launchProject": "Base",
    "launchConfig": "flobi-wan-kenobi-gustavgerig-dev-deployment"
  }
}
```

| Field | Rule |
|---|---|
| `version` | Integer `1`. Anything else → `invalid`. |
| `target.launchProject` | Non-empty folder path relative to `<repo>`, `/` or `\` separators; not rooted, no `..` segment. |
| `target.launchConfig` | Non-empty string; matched **ordinal, case-sensitive** against `configurations[].name`. |
| other keys | Preserved on write, ignored on read (reserved for later per-repo, per-developer values). |

**States** (evaluated in this order):

| State | Condition |
|---|---|
| `noToolkit` | No `aldc.yaml` found under `<repo>` (§ location). |
| `absent` | File does not exist. |
| `invalid` | Not parseable as strict JSON, not an object, or a field rule above fails. `reason` names the rule. |
| `stale` | `<repo>/<launchProject>/.vscode/launch.json` missing or unparseable, no configuration with that exact `name`, or the matching configuration has no `server`. |
| `configured` | Otherwise. `resolvedLaunch` and `issues` (§2.3) are filled. |

**Writing.** Only three writers: the extension's *Select AL Target* command (§4.4), `Set-AprodaAlLocalSelection`
(§3.2, used by the agent after the DRV environment question), and a human. Writes are atomic (write
`aldc.local.json.tmp`, then rename over the target). A writer never touches `launch.json`.

**Git.** Ignored through the managed block (`/.github/aldc.local.json`, `/aldc.local.json` — rollout §3).
Never on the `aproda-sync.json` allowlist.

### 2.3 Resolved launch configuration and target bundle

`launch.json` is parsed as JSONC (pwsh 7 `ConvertFrom-Json` accepts comments and trailing commas — C-5;
the extension uses `jsonc-parser`). From the configuration `c` that matched `launchConfig`:

| Field | Derivation | Blocking issue code if violated |
|---|---|---|
| `name` | `c.name` | — |
| `server` | `c.server`, trailing `/` removed; must be an absolute `http`/`https` URL without path, query or port | `SERVER_INVALID` |
| `scheme`, `host` | from `server`; `host` keeps the case written in `launch.json` | — |
| `serverInstance` | `c.serverInstance`, non-empty | `INSTANCE_MISSING` |
| `port` | `c.port` if integer 1–65535; absent → `7049` (AL default) with `portSource: "default"` | `PORT_INVALID` |
| `tenant` | `c.tenant` if non-empty, else `default` | — |
| `environmentType` | `c.environmentType`; absent → `OnPrem` (a `server` configuration is OnPrem) | `NOT_ONPREM` if present and ≠ `OnPrem` |
| `authentication` | `c.authentication`, normalized to `Windows` / `UserPassword` (case-insensitive) | `AUTH_MISSING`, `AUTH_UNSUPPORTED` (`AAD`, `MicrosoftEntraID`), `AUTH_UNKNOWN` |
| — | `UserPassword` with `scheme = http` | `USERPASSWORD_OVER_HTTP` |
| `dependencyPublishingOption` | `c.dependencyPublishingOption` if one of `Default`, `Ignore`, `Strict`; absent → `Default` | `DEPENDENCY_OPTION_INVALID` |
| `credentialKey` | `host` (same key as D-43 and the prototype) | — |

`issues` is an array of `{ code, message }`; every code above is **blocking** for target operations
(publish, test run, MCP target environment), never for build-only. Messages name the `launch.json` path and
the configuration name; they never contain credential data.

**Target bundle** — the only shape any target call is built from (C-1, C-2):

| Bundle field | MCP `al_publish` / `al_run_tests` parameter | `altool` option | Direct POST |
|---|---|---|---|
| `ServerUrl` = `scheme://host` | `serverUrl` | `--server` | URL base |
| `ServerInstance` | `serverInstance` | `--serverinstance` | path segment |
| `Port` | `port` | `--port` | URL port |
| `Authentication` | `authentication` | `--authentication` | handler choice (§6.4) |
| `Tenant` | `tenant` | `--tenant` | `tenant=` query |
| — | — | `--environmenttype OnPrem` | — |

### 2.4 `altool` locator (C-7)

Order, first hit wins:

1. **Explicit extension path** (`-AlExtensionPath`, passed by the Aproda extension from
   `vscode.extensions.getExtension('ms-dynamics-smb.al').extensionPath`): `bin\altool.exe`, else
   `bin\win32\altool.exe`. Missing → error `ALTOOL_NOT_IN_ACTIVE_EXTENSION` (no search — the active extension is
   authoritative). `Version` = `packageJSON.version` passed alongside, else parsed from the folder name.
2. **Installed extensions** under `$env:USERPROFILE\.vscode\extensions`:
   - candidates: directories `ms-dynamics-smb.al-*`, **minus** names listed with value `true` in the JSON file
     `.obsolete` in that folder (VS Code's pending-deletion list);
   - name must match `^ms-dynamics-smb\.al-(?<v>\d+\.\d+\.\d+)(?:-(?<platform>[a-z0-9-]+))?$`; a non-matching
     candidate → error `ALTOOL_UNPARSABLE_VERSION` (C-7: stop, never guess);
   - highest `[version]` wins; two candidates with the same highest version → error `ALTOOL_AMBIGUOUS`;
   - binary as in step 1; folder without binary → error `ALTOOL_MISSING_IN_EXTENSION`.
3. **dotnet tool** `al` on `PATH` (D-34): accepted with warning `ALTOOL_FALLBACK_DOTNET_TOOL` (version may differ
   from the editor's compiler), `Version = $null`.
4. Nothing found → error `ALTOOL_NOT_FOUND`.

Never by `LastWriteTime`.

### 3.3 Starter `Start-AprodaAlMcp.ps1`

```powershell
param(
    [Parameter(Mandatory)][string]$RepositoryRoot,
    [Parameter(Mandatory)][string]$SkillRoot,          # <...>/skills/skill-aproda-al-mcp (C-6)
    [string]$AlExtensionPath,                          # active AL extension root (C-7 step 1)
    [string]$AlExtensionVersion,
    [switch]$DryRun
)
```

**Stdout is the JSON-RPC channel (C-4).** Before `altool` starts, nothing may reach stdout:
`$ProgressPreference`, `$InformationPreference`, `$WarningPreference`, `$VerbosePreference` = `SilentlyContinue`
(defence against `Write-Warning` in `Get-FkhStoredCredential`); all diagnostics through
`[Console]::Error.WriteLine('[al-mcp-starter] <LEVEL> <CODE> <text>')`; no `Write-Host`/`Write-Output`.

Sequence:

1. pwsh < 7 → `ERROR PWSH_TOO_OLD`, exit 5. `RepositoryRoot` and `SkillRoot` are normalized with
   `[IO.Path]::GetFullPath` (the interim registration passes `${workspaceFolder}\..`).
2. Load `AprodaAlTarget.ps1` from `$SkillRoot\scripts\` and `FkhCredentialStore.ps1` from
   `$SkillRoot\..\skill-aproda-fkh\scripts\`. Failure → `ERROR LIBRARY_LOAD_FAILED`, exit 6.
3. Projects (`Get-AprodaAlProjects`). None → `ERROR NO_AL_PROJECT`, exit 4.
4. `Find-AprodaAlTool`. Error → `ERROR <ALTOOL_*>`, exit 3. Warnings → stderr.
5. Remove inherited `BC_SERVER_URL`, `BC_SERVER_INSTANCE`, `BC_SERVER_PORT`, `BC_SERVER_USERNAME`,
   `BC_SERVER_PASSWORD`, `BC_ACCESS_TOKEN` from the starter's own process environment (never inherit a partial
   target — C-1).
6. Determine the mode:

   | Condition | Mode | stderr code |
   |---|---|---|
   | selection `configured`, no issue, `Windows` | `target` | — |
   | selection `configured`, no issue, `UserPassword`, credential found for `credentialKey` | `target` | — |
   | `UserPassword`, no stored credential | `buildOnly` | `WARN CREDENTIAL_MISSING <host>` |
   | selection `absent` / `invalid` / `stale` / `noToolkit` | `buildOnly` | `WARN SELECTION_<STATE>` |
   | blocking issue(s) | `buildOnly` | `WARN TARGET_BLOCKED <codes>` |

   In `buildOnly` every target call fails at call time with the server's own error; build, compile,
   diagnostics and symbol tools work (finding 3: never remove the whole tool set).
7. `target` mode: set `BC_SERVER_URL` (= `ServerUrl`), `BC_SERVER_INSTANCE`, `BC_SERVER_PORT`; for
   `UserPassword` also `BC_SERVER_USERNAME`, `BC_SERVER_PASSWORD` (from the store). Process scope only.
8. `Test-AprodaAlFirstConfiguration` warnings → `WARN FIRST_CONFIG_DIFFERS <project>` (C-1, informational).
9. `-DryRun`: write one line `[al-mcp-starter] PLAN <json>` to stderr with
   `{ mode, reasons[], altool{path,version,source}, projects[], envNames[], warnings[] }` — environment
   **names** only, never values — then exit 0.
10. `& <altool> launchmcpserver <project paths...> --transport stdio`; `exit $LASTEXITCODE`.

| Exit | Meaning |
|---|---|
| 0 | Dry run finished, or `altool` exited 0 |
| 3 | `altool` not found / ambiguous / unparsable version |
| 4 | No AL project under the repository root |
| 5 | pwsh < 7 |
| 6 | Library or credential store could not be loaded |
| other | Passed through from `altool` |

### 4.3 MCP server definition provider (X-12)

- **`provideMcpServerDefinitions`**: returns `[]` when the window is not an AL workspace (no workspace folder with
  `app.json` at its root — the existing `isAlWorkspace()` rule behind `aprodaAldc.isAlProject`), when the start
  mode is `manual` and no start was requested in this window (§4.3a), when the repository does not resolve
  (`resolveAldcRepository().state !== "configured"`), or when
  `<toolkitRoot>/skills/skill-aproda-al-mcp/scripts/Start-AprodaAlMcp.ps1` is missing (logged once).
  Otherwise exactly one `vscode.McpStdioServerDefinition`:

  | Field | Value |
  |---|---|
  | `label` | `al-mcp` (unchanged from the prototype so tool names stay comparable; Q-5) |
  | `command` | `pwshPath()` (setting `aprodaAldc.pwshPath`) |
  | `args` | `-NoProfile`, `-NonInteractive`, `-Command`, `& ([ScriptBlock]::Create((Get-Content -LiteralPath '<starter>' -Raw))) -RepositoryRoot '<repo>' -SkillRoot '<skill>' -AlExtensionPath '<alExt>' -AlExtensionVersion '<ver>'` — single quotes inside paths doubled; `-AlExtension*` omitted when the AL extension is not installed |
  | `cwd` | `<repo>` |
  | `env` | `{}` — the extension never passes target or credential values |
  | `version` | first 12 hex chars of SHA-256 over: selection file bytes, `resolvedLaunch` JSON, credential-present flag, AL extension version, `aproda.layerVersion` |

- **`resolveMcpServerDefinition`** (runs right before start, may show UI, never blocks on a terminal):

  | Situation | Behaviour |
  |---|---|
  | selection `absent` / `stale` / `invalid` | Notification *"No valid AL target for AL MCP."* `[Select target]` (runs §4.4) `[Start build-only]`; returns the definition either way |
  | `UserPassword`, credential absent (§4.5) | Notification *"No stored credential for <host>."* `[Store credential]` (runs §4.5 flow) `[Start build-only]`; returns the definition |
  | blocking issue | Notification naming the issue codes; returns the definition (build-only) |
  | otherwise | returns the definition |

- **`onDidChangeMcpServerDefinitions`** fires (debounced 500 ms) on changes of: the selection file, the
  selected project's `.vscode/launch.json`, the credential store folder, the setting `aprodaAldc.alMcp.start`,
  the workspace folders (`onDidChangeWorkspaceFolders`), and AL extension install/update
  (`vscode.extensions.onDidChange`). A changed `version` makes VS Code restart the server with the new target and
  credential (trust behaviour: Q-24).
- Start failure: VS Code shows the MCP error; the provider additionally logs the last starter exit code to the
  *Aproda ALDC* output channel (finding 3 — never silent).

### 4.3a Start mode (`aprodaAldc.alMcp.start`)

VS Code itself only starts MCP servers lazily: its (experimental) autostart pass, setting `chat.mcp.autostart`
(`never` | `onlyNew` | `newAndOutdated`, default `newAndOutdated`), starts servers when a chat message is
submitted. The extension therefore controls the start itself:

| Mode | AL workspace open | Behaviour |
|---|---|---|
| `auto` (default) | yes | Provider returns the definition. After activation, and when the window becomes an AL workspace, the extension calls `workbench.mcp.startServer` for its server **once** (Q-23), so the tools exist before the first chat message. If that call is unavailable, VS Code's autostart pass on the first chat message remains the start path (works unless `chat.mcp.autostart = never`; the doctor reports that combination). |
| `manual` | yes | Provider returns `[]` until a start is requested in this window — command *Aproda ALDC: Start AL MCP Server* or the `startAlMcp` tool (§4.7). The request sets a window-scoped flag, fires `onDidChangeMcpServerDefinitions`, then calls `workbench.mcp.startServer`. Returning `[]` before that keeps VS Code's autostart pass from starting the server behind the user's back. The flag resets on window reload. |
| either | no | Provider returns `[]`; nothing starts. |

Switching `auto` → `manual` at runtime removes the definition (VS Code stops the server) unless a start was
already requested in this window; `manual` → `auto` provides it and starts it once. The first start of an
extension-provided server shows VS Code's MCP trust dialog once (MCP server trust); that dialog is VS Code's,
not ours, and is not suppressed.

### 6.4 Publish route

`Invoke-DeployRunVerifyPublish -Cfg <object>` replaces `Invoke-DeployRunVerifyDeployAsinst` and the publish

1. Fkh only: `Resolve-DeployRunVerifyFkhContainer` (unchanged, target verification).
2. **a. `altool publishapp`** (if `PublishApp` capability and not pinned):
   `publishapp <AppFile> --server <ServerUrl> --serverinstance <inst> --port <port> --authentication <auth> --tenant <tenant> --environmenttype OnPrem --schemaupdatemode <mode> [--forceupgrade]`
   — no `--project` (nothing may merge from `launch.json`).
3. **b. Direct POST** `Publish-DeployRunVerifyDevEndpoint` (if a. unavailable or classified

   multipart (`StreamContent`, disposition `form-data`, name/filename/filename* = file name), `ExpectContinue = $false`,
   infinite timeout; `Windows` → `UseDefaultCredentials = $true`; `UserPassword` → HTTPS only, ASCII-only
   credential (Q-19, else error `CREDENTIAL_NON_ASCII`), in-memory Basic header built by the internal helper
   `New-DeployRunVerifyBasicAuthorization -Credential` (returns an `AuthenticationHeaderValue`, testable without a
   server), `UseDefaultCredentials = $false`;
   dispose everything; never log headers. `forceUpgrade` is not supported on this route → error

4. **Verify state** (both routes): ASINST `Get-NAVAppInfo -ServerInstance -Tenant -TenantSpecificProperties -Name`
