## 2. Live targets and safety rules

| Target | Transport | Auth | Company | Allowed writes |
|---|---|---|---|---|
| `TOGA_FOOD_SA_28_AG_28_CH_FKO` (`apd-svw-nst05`, BC 28.0) | ASINST, HTTP 9540 | `Windows` | `CRONUS (Schweiz) AG` | Gustav Base/Test with `Synchronize`; disposable `E010 Recovery Probe` for anything destructive |
| `flobi-wan-kenobi-gustavgerig-dev-deployment` (BC 28.3) | Fkh, HTTPS 7049 | `UserPassword` (Fkh store) | `CRONUS CH` | same |

Rules for every `L-*` case:

1. Environment acknowledgement once per test session; every Tier-3 action (`Recreate`, `forceUpgrade`,
   removal) needs its own explicit confirmation. Destructive schema tests (`ForceSync`) run **only** against the
   disposable probe app, even though D-39 itself needs no separate confirmation.
2. Never remove the historical leftover Base `25.0.0.156` as part of a test (evidence artifact).
3. No password, header, token or credential value in any output, file or report.
4. Each result records: date, target, auth, AL Language version, `altool` version, route per step, counts,
   durations, and the exact command (secrets excluded).
5. A failed live case stops the phase gate; the fix goes through the normal review, then the case is repeated.
